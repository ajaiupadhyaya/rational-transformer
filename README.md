# The Rational Transformer

Small causal transformers trained from scratch, only to minimise squared forecast error, on
AR(1) sequences with persistence drawn from U[0, 1]. Each is compared with the exact Bayes
forecaster that holds the same prior and the same window of data ("window-Bayes"). Hypotheses,
margins and decision rules were frozen in a pre-registration before any confirmatory run.

**Status: complete.** All 96 planned runs finished.

| Hypothesis | Result |
|---|---|
| H1: the largest model with full memory is equivalent to Bayes | supported, 12 of 12 verdicts |
| H2: with memory cut to W = 2, 4, 8, 16, the largest model is equivalent to window-Bayes | equivalent at every window, 12 of 12 each |
| H3: overreaction beyond window-Bayes at ρ = 0.6 and 0.8 | not supported, 0 of 8 combinations |

**Paper:** *The Rational Transformer: What a Network Trained to Forecast Gets Wrong, and Whether It
Is Bias or Missing Information* (`docs/paper/`, rendered `docs/paper/_output/paper.pdf`).
Zenodo: [doi:10.5281/zenodo.24387529](https://doi.org/10.5281/zenodo.24387529) ·
SSRN: [abstract 7733526](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=7733526) (under review).
Every number in it is generated from the results files by `analysis/paper_build.py`. A shorter
report-series edition for the author's site is in `paper/the-rational-transformer/`.

## Where things are

| Path | What it is |
|---|---|
| `docs/PREREG.md` | The pre-registration, frozen at tag `prereg-v1`. It describes the grid as first planned (six checkpoints, 125 runs). |
| `docs/DECISIONS.md` | Every decision and deviation, with timing. The grid actually run (96 runs, Plan A) is the `prereg-v1.1` entry. Dates there are UTC. |
| `RESULTS.md` | All verdicts with seed values, generated by `python -m analysis.report`. |
| `results/metrics/` | One evaluation CSV per run: the input to every verdict. |
| `results/summary.csv`, `results/hypotheses.json` | Aggregated results. |
| `figures/` | The four figures in the report. |
| `rt/` | Simulator, exact Bayes and window-Bayes benchmarks, model, training, evaluation, gate. |
| `analysis/` | Seed-level intervals, verdicts, H1–H3, figures, the survey comparison. |
| `cloud/`, `scripts/` | How the sweep was run on one rented GPU and a laptop. |
| `data/` | Small derived inputs; sources and checksums in `data/PROVENANCE.md`. |

Tags `prereg-v1` to `prereg-v1.4` mark the pre-registration and its deviations. Do not rewrite
history: the tags pin the frozen code.

## Reproduce

Everything uses [uv](https://docs.astral.sh/uv/).

```
uv sync
uv run pytest                                   # 159 tests, about 2-3 minutes
uv run python -m rt.gate                        # benchmark, planted-value and learning checks
uv run python -m analysis.report                # RESULTS.md, results/*.csv/json, figures/
```

`analysis.report` reads `results/metrics/`, which is in the repository, so the verdicts can be
recomputed without training anything.

To retrain, run `python -m rt.sweep` (see `cloud/README.md` and `scripts/mac_sweep.sh`).
Training is seeded per step, so a run follows the same data stream on any machine. Numbers
agree to floating-point tolerance, not bit for bit. Cloud runs used TF32 matrix multiplies, so
their fourth decimals depend on it.

## Not in the repository

- **Model checkpoints (about 6 GB) and the benchmark cache (about 9 GB).** Both are too large.
  The cache is rebuilt by `rt.evaluate`. Checkpoints for seven primary runs (`A-l-w8-s0` to
  `s4` and `A-l-w4-s4`, plus the earlier steps of `A-l-w16-s0`) were lost with a cloud
  instance. Their evaluation CSVs were copied before that and are complete.
- **The AKLMT replication package.** Only six rows of published summary statistics are used
  (`data/aklmt_figure2.csv`).
